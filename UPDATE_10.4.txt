KITCHEN HUB 10.4 - SIDE RAIL, PANTRY, PRIVACY PIN, LOCKED BOOKS AND FIXES
Install: upload the kit to GitHub like before (everything, including the .github folder). Replace
kindle/shiftcal/mesquite/index.html with the patched one (kindle_mesquite_index.html). A fridge set to
"At night" installs it after 2 am; to have it now, Settings > Phone > CHECK FOR UPDATE (tap twice).
The phone app updates itself the next time you open it.

BEFORE YOU UPLOAD
 *  GitHub > your repo > Settings > Secrets and variables > Actions: HUB_PASS must be exactly your
    PASSPHRASE from cloud.conf. Without it the cloud can't lock (or convert) books.
 *  If your passphrase has spaces, put it in quotes in cloud.conf:  PASSPHRASE="four random words here"
    (cloud.conf is read as a shell file - without quotes only the first word counts).
 *  If cloud.conf has no PASSPHRASE line, the hub has been using a built-in one. Set your own (and the
    same HUB_PASS), then pair the phone again.

NEW ON THE FRIDGE
 A  Side rail: the left edge shows the time and the apps you opened, newest first. Tap one to jump
    back, or HOME for the tiles. HIDE gives the full width back; APPS > Side rail brings it back.
 B  Pantry app: USE FIRST (expiry board), EVERYTHING (by place, with amounts), COOK (saved recipes
    that use what's going off) and SETTINGS (places, shelf days, and a switch for each feature).
 C  Pantry on the phone: a PANTRY tab. Food ticked off the shopping list goes into the pantry, and
    staples that drop below their keep-at-least go back on the list once (the cloud brain does this).
 D  Privacy PIN: each person can set a PIN in the Privacy app. Their Money, Notes, Board and Pay tiles
    stay locked until it's typed, and lock again after 5 minutes (changeable) or when the Kindle
    sleeps, so the screensaver can't show them. The phone and TV page aren't locked.

LOCKED BOOKS
 1  Every book in your book cloud is locked with your passphrase before it reaches GitHub (AES-256).
    The phone locks uploads itself; the cloud locks Gutenberg books, articles and converted EPUBs.
 2  Books stored before 10.4 are locked by the cloud brain, two per run.
 3  The fridge unlocks books as it downloads them (openssl) and checks each one byte for byte.
    DOWNLOAD on the phone unlocks them too.
 4  No more DRM notes: whatever you upload is stored as it is.

SAFER CONNECTIONS (fridge)
The fridge used to skip the certificate check on every download (curl -k), because older Kindle firmware
has an outdated list of trusted certificates. Now it tries a checked connection first. Once that works,
the fridge never goes back to unchecked ones, so a fake GitHub on your Wi-Fi can't read your token or slip
in a fake update. Kindles whose list really is too old keep working unchecked and try again every day.
If checked connections stop working for 3 days in a row, the fridge falls back so it can still update,
and writes it in the log. New file: kindle/shiftcal/kcurl.sh. To start over, delete .tls in the shiftcal folder.
