KITCHEN HUB 10.9.4 - CLEANUP AFTER THE FIRST REAL START
Installs by itself like any update: Settings > Updates > CHECK FOR UPDATE.

FIX
 1  The start-up error box stayed on the screen after the hub had started. It now clears itself as soon as
    the hub is running, and only shows up at all if the hub can't start.
 2  The box (and the log) listed "a file failed to load: horo.js". That file is optional (the hub makes its
    own horoscopes when it's missing); such files are now noted once in the log, never on the screen.
 3  "JavaScript execution exceeded timeout": the 10.9.2 start-up black box reported every step on the spot
    and made the page wait for each one, so start-up took about 19 s instead of ~10 and the Kindle's
    browser cut a script short. Steps are now only remembered; errors are still reported.
 4  data.js (weather and news) wouldn't load on the Kindle: "Parse error" on its news line. Invisible
    line-separator and control characters from news text (fine for the cloud's newer JavaScript, not for
    the Kindle's older engine) are now cleaned out in the cloud and on the Kindle. If data.js ever fails
    again, the log describes the failing line, so the cause can be pinned down.

FROM 10.9.3
 5  THE CAUSE of every 10.9 rollback (blank screen): while the page started, a 10.9 step that re-sends
    list items the Kindle file was missing wrote a note through a helper whose memory was only set up
    ~1900 lines further down the page. On a Kindle with saved list items that crashed the page's
    start-up, so it never said "I'm up". The 10.9.2 black box caught the exact error. The helper is set
    up first now, and a list hiccup can no longer stop start-up. Reproduced and confirmed fixed in an old
    browser like the Kindle's, with list items of every kind.
 6  GitHub's upload check now also scans the page for start-up code that reads something before it is
    set. It flags 10.9.2 and passes 10.9.3, so this kind of bug can't reach the fridge again.
 7  The weather in data.js could be a cut-off download (it only had to contain the words "hourly" and
    "daily"), which made data.js fail to load: no weather or news. The cloud now leaves out any file that
    isn't valid, and the Kindle only uses a whole weather reply.
 8  10.9 turned the frontlight OFF every time it started or woke (the new light setting defaulted to
    Off). Now the hub leaves the light alone unless you pick a level in Settings > Sleep > Light while
    you use it ("Kindle's own" is the default).

SECURITY
 9  Authenticator codes: Settings > Security > SET UP shows a code for Google or Microsoft Authenticator.
    After that, pairing codes, the first cloud connection and new keys need a fresh 6-digit code.
10  Pairing codes are sealed: the QR holds everything locked with a one-time code shown next to it, never
    inside it. A copied or photographed link alone opens nothing. The shopping-list QR only opens the app.
11  MAKE NEW KEYS: the Kindle makes a new passphrase, alert channel and monitor channel itself. Old
    lists and books still open until you tap FINISH; the screen walks you through the GitHub secrets.
    Fridges that used the old built-in passphrase are told to do this.
12  A new GitHub token goes in on the phone (Fridge > New GitHub token); the fridge picks it up itself.
13  The fridge's settings port needs a key now, so other devices on your Wi-Fi can't stop the hub, undo an
    update or send phone alerts. Fixed: a phone alert could be made to send a file off the Kindle.
14  The phone app and TV page are hidden from search engines and do nothing until paired. The PC helper
    asks for the pairing link (it no longer stays in PowerShell's history) and locks its saved token.

BATTERY
15  Timer wakes are quick: the fridge refreshes the asleep screen in a few seconds and sleeps again,
    instead of staying awake for 2 minutes with nobody there (and flashing the screen twice). The power
    button, or a tap while it refreshes, opens the hub as before. Settings > Sleep > Timer wakes.
16  The asleep clock is honest: the exact time and "until 6:00 PM" (at night, "back at"). Or choose
    "every minute": a 3-second wake each minute changes just the time (no Wi-Fi, no touch).
17  Settings > Sleep shows how much battery an hour it uses lately, to compare settings. New: a light
    setting for while you use the hub (off asleep), or leave it to the Kindle (the default).

HOME SCREEN
18  Spare room goes to tiles whose content didn't fit; an empty shopping list or idle timer shrinks.
19  Small cards fill leftover space: bird of the hour, tomorrow's shift, sunrise or sunset, the next
    holiday or event. No more blank holes.
20  Live boosts: a running timer, rain or a storm in the next 3 hours, or a shift within 2 hours makes
    that tile bigger (up to two, kept at least 30 minutes so the screen doesn't jump).
21  Bird of the hour: birds of Prince George for the season, with real photos (free-licence Wikimedia
    Commons pictures, photographer credited).

KITCHEN MONITOR
22  APPS > Kitchen screen controls the TV page on a mini PC: dashboard, big clock, your timer, a tavern
    menu board, the week, news, screen off, cook a recipe step by step. Pair the monitor once:
    Settings > Security > TV / MONITOR. Commands are locked and can't be replayed.
23  See-through look for transparent screens: black is clear glass, the type is warm and bright.

SYSTEM
24  Settings > System (was Log): a task manager - CPU, memory, storage, battery, the busiest programs and
    the Kindle's own services. It only looks; the list goes to your cloud log so a later "hub mode" can
    pause only services that are safe to pause on your Kindle.

FIXES
25  Changes made on the fridge could get lost when its background loop was busy; they're sent one batch
    at a time now, retried, and sent again if the fridge's file doesn't have them.
26  The cloud brain can't hang any more when GitHub or ntfy doesn't answer (it stops after 45 s).
27  The asleep front page no longer cuts a story in the middle of a symbol.
